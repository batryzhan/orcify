# Three-minute live demonstration

Before presenting: run `npm run dev`, open the local URL, and choose Research overview.
Use the Presentation demo mode, which needs no database, credentials, or Internet.
Do not imply that the saved plan is generated by an AI during the demonstration.

**0:00–0:30 — The problem.** “A creative campaign is a set of connected assets.
Changing a slogan can affect copy, captions, and a storyboard. Rebuilding everything
may waste work, but keeping stale work is risky. Our question is how to decide what
changes while keeping human approval explicit.”

**0:30–1:00 — Read the graph.** Open Graph & impact. “This is the original small
synthetic slogan-change fixture. Nodes are versioned requirements and assets. HARD
links mean mandatory dependency; SOFT links mean the impact may depend on the field
that changed. This mode is explicitly a saved offline preview.” Select Campaign slogan
and inspect its version and confirmed source.

**1:00–1:40 — Preview the change.** Click Preview slogan change. “The proposed text
changes from ‘Made to move’ to ‘Made to move — revised’. Copy, captions, and storyboard
must be recomputed. The social export has uncertain impact and waits for review;
its HARD child, logo, also waits. The social visual's palette-related SOFT dependency
is disjoint from the text change, so this fixture keeps it.” Select a node to show
the actual planner reason, input versions, and typed link. “These are six asset
decisions. Nothing has been generated or approved.”

**1:40–2:25 — Compare fairly.** Open Experiments & results. “In the five-case initial
pilot, counts were 24, 21, and 12. But eight operations behind the apparent difference
were deferred for review.” Open Review & replan. Toggle all four branches from
non-material to material. “Final GAMO-CA recomputations rise from 12 to 20. Field-aware
DAG matches throughout. These cases do not demonstrate superiority over a comparable
DAG.” Point out the saved planner timing table and its unequal-work caveat.

**2:25–3:00 — The conclusion.** “The prototype makes uncertainty and approval gates
visible. It does not demonstrate scientific novelty, real savings, or general safety.
Independent reviewer data is still missing. Approval, provenance, and recovery are
engineering safeguards; their benefit needs comparison against a simpler DAG with
the same safeguards.” Return to the graph and click Reset demo to show repeatability.

If the optional Live API view is requested, explain that it uses authenticated
PostgreSQL state and requires local services. If those services are unavailable,
show the explicit error and return to Presentation demo. Never describe a saved
preview as a live backend execution.
