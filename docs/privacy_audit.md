# Аудит приватности: Local Anonymizer и Zero-PII Logging

Документ фиксирует, **какие данные и куда** уходят в каждом сценарии, какие механизмы это гарантируют
и как это проверено (тесты + замер на синтетическом наборе). Все примеры — синтетические.

## 2. Как работает LocalAnonymizer

1. **Регулярные выражения** (детерминированно): ИИН/БИН (12 цифр; БИН — по 5-й цифре 4/5/6), телефоны РК/РФ,
   email, IBAN `KZ…`, номера карт, компании с организационно-правовой формой (`ТОО «…»`, `АО «…»`, `LLP «…»`, `ИП Фамилия`).
   Найденное вырезается из рабочей копии, чтобы шаблоны не пересекались (карта внутри IBAN).
2. **Локальная LLM** (Structured Output `PiiDetectionResult`): ФИО, бренды без формы собственности, адреса.
   Принимаются только фрагменты, **реально присутствующие в тексте** — галлюцинации отбрасываются.
3. **Псевдонимы**: для компаний — название без формы и кавычек, слитное написание (`#альфатрейд`);
   для людей — отдельные слова ФИО. Все варианты маскируются тем же токеном, без учёта регистра.
4. **Замена за один проход** общим регулярным выражением (длинные значения раньше коротких) —
   короткое значение не может повредить уже вставленный токен.
5. **Проверка утечки**: перед внешним вызовом считается `leaked_json()` — сколько зарегистрированных
   значений и псевдонимов осталось в аргументах. Больше нуля — вызов запрещён.
6. **Время жизни таблицы соответствия**: объект `AnonymizationSession` в памяти запроса, `clear()` в `finally`
   сразу после последнего внешнего вызова. На диск таблица не пишется никогда.

Если LLM-детектор недоступен, сессия строится только по регулярным выражениям (деградация полноты, а не отказ).

## 3. Найденная и исправленная утечка (живой прогон)

Во время сквозного прогона Сценария Б Gemma написала в заголовке и хэштегах название компании **без**
организационно-правовой формы: «Альфа Трейд», `#альфатрейд`, `#тооальфатрейд`. Анонимайзер знал только
полную форму «ТОО «Альфа Трейд»», поэтому собственная проверка утечки показала 0, а название ушло в очередь
синхронизации Jira.

Исправление: псевдонимы (п. 2.3) + регистронезависимое сравнение. Добавлен регрессионный тест
`test_aliases_catch_bare_names_and_hashtags`; повторный живой прогон — в очереди только `[COMPANY_1]`, `[PHONE_1]`.

Вывод для работы: **проверка «утечек нет» ограничена тем, что анонимайзер знает**. Поэтому PII Leakage Rate
ниже считается по независимому эталону (заранее размеченные значения), а не по самоотчёту анонимайзера.

## 5. Zero-PII Logging

- `SafeLogger` принимает только поля из белого списка (`session_id`, `task_id`, `payload_hash`, `domain`,
  `latency_ms`, `status`, `error_code`, счётчики…). Любое другое поле — `ValueError` (проверяется тестом).
- Строковое значение длиннее 128 символов отклоняется: так сырой текст не пролезет даже в разрешённое поле.
- Ошибки Pydantic и Jinja перехватываются с `from None`: их `input_value` (возможные PII) не попадает
  в трассировки. Ошибка ИИН/БИН не содержит самого номера (проверяется тестом и в API-ответе 422).
- Локальный MCP-сервер возвращает ожидаемые ошибки машинным кодом (`finance_input_error:…`) без трассировки.

## 6. Хранение

| Что | Где | Сколько |
|---|---|---|
| Текст задачи, CSV | память (`TaskStore`) | до подключения к стриму, максимум 5 мин |
| Готовые документы | память (`DocumentStore`) | 1 ч |
| Таблица соответствия PII | память (`AnonymizationSession`) | до конца запроса |
| Очередь синхронизации | `backend/var/sync_queue.jsonl` (в `.gitignore`) | до ручной синхронизации; **только токены** |
| Логи | stdout | только поля белого списка |

## 7. Ограничения

- Регулярные выражения не ловят ФИО и названия без формы собственности — это зона LLM-детектора, его полнота
  меньше 100% (см. п. 4). Для критичных данных пользователь видит в UI, что именно ушло наружу (блок
  «Что ушло во внешние сервисы» с подсветкой токенов).
- Морфология: падежные формы, отличающиеся от зарегистрированной («Иванову» при «Иванов»), маскируются по
  подстроке основы; формы с чередованием (Пётр → Петра) — только если их вернул LLM-детектор.
- Внешние MCP-серверы в замерах подменены in-process серверами, фиксирующими входящие аргументы (интеграционные
  тесты `test_mcp_and_scenarios.py`); с реальными Higgsfield/Atlassian проект не тестировался — нужны учётные данные.
